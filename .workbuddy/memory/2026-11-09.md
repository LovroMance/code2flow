## 源码获取与节点跳转链路梳理（原理答疑，未改代码）

用户提出两个"无法攻破"的问题，实际排查后发现**均已在项目中完整实现**，属概念未对齐而非代码缺失。

### 问题1：上传文件如何获取源码 / 是否需要工具给智能体调用

结论：已实现，且有两条独立通道。

- 前端读取：`frontend/src/features/workspace/model/useWorkspacePage.ts` 的 `handleUploadFiles`
  用 `file.arrayBuffer()` + `TextDecoder('utf-8',{fatal:true,ignoreBOM:true})` 在浏览器读原文。
  后端不读本机磁盘（与 AGENTS.md「不读取上传路径所指的本机文件」一致）。
- 提交快照：`POST /v2/sessions/:id/snapshots`（`frontend/src/shared/api/multifile.api.ts`）。
- 后端落库：`backend/src/repositories/source.repository.ts` 的 `create()`。
  正文按 sha256 存 `code_flow_source_blobs`（内容寻址去重）；行偏移表存 `code_flow_source_positions`（按 hash 缓存）；
  快照 `code_flow_snapshots` 只存 manifest + 文件元数据。相同 manifestHash 直接复用旧快照。
- 取回正文：`content(snapshot, fileId)` 先校验 fileId 属于该快照，禁止跨快照读取。
- **智能体工具已存在**：`backend/src/services/source-context.service.ts` 的 `tools()` 返回
  `read_code`（≤8选择器/200行/12000字符，读后登记 Evidence）、`list_files`、`get_file_index`、`search_code`。
- 工具化的真正理由不是省 token，而是**证据链**：`SourceContext.validate` 用 evidenceId 区间覆盖模型声称的行号区间，
  模型无法凭空编行号。这是项目核心技术亮点，不可拆分。

### 问题2：点击图节点跳转到源码位置

链路已完整闭环：

```
mappings(fileId+行列) → buildInteractiveMermaid 追加 click 指令
  → useMermaidRenderer 挂 window.code2flowNodeClick（需 securityLevel:'loose'）
  → FlowDiagram emit select-node
  → WorkspacePage.vue:74 handleSelectNode
  → useWorkspacePage.primeFollowUpQuestionFromNode 切换 activePath
  → CodeEditor.vue focusMapping
  → revealLinesInCenter + setSelection + deltaDecorations 整行高亮
```

坐标陷阱与处理（`frontend/src/features/code-editor/model/mappingSelection.ts` + `backend/src/utils/sourcePositions.ts`）：
BOM 列号偏移修正、CRLF 保留、代理对 `safeBoundary` 禁止从中间截断、
**偏移是唯一真值 / 行列是派生**、`validateSourceRange` 不一致直接报错不静默修正。
跳转四步顺序不可乱：切文件 → 等 model 就绪（`pendingMapping`）→ 滚动 → 选区/装饰。

核心设计：**图节点指向 fileId 而非路径**，故重命名不影响跳转；快照不可变 + manifestHash 比对，
避免「旧图混新源码」导致行号静默错位。

### 已识别但未实现的 4 个缺口（用户选择暂不改代码）

1. 追问回答中的行内引用（如 `src/foo.ts:42`）不可点击 —— 收益最高
2. 跳转失败静默（`mappingFilePath` 返回 undefined 时无用户反馈）
3. 无反向跳转（编辑器光标移动不高亮对应节点）
4. 单文件上传走 `startSession` 不建快照，拿不到 fileId，无法复用证据链

## 预算参数与读取可靠性评估（追加）

### read_code 单次预算（`SOURCE_LIMITS`，backend/src/services/multifile-config.ts）
selectors 8 / readLines 200 / readChars 12000 / searchLimit 8 / snippetChars 400 / pageSize 20 / maxVectors 2000 / maxFileBytes 204800。
配套：index 任务最多 4 次模型调用，generate 只有 1 次（`modelCallLimitMiddleware`）。

### 全局预算（AnalysisBudget，默认值）
maxCalls 120 / maxInput 600000（index+verify 只给 80% = 480000）/ maxOutput 80000 /
outputTokens 4000 / timeout 900000 / retries 1 / chunkLines 60 / chunkChars 2000 / concurrency 3。
`CODE2FLOW_MODEL_CONTEXT_TOKENS` **无默认值，不填直接抛配置错误**。

### 重要认知修正：当前不是纯 agentic
`multifile-runtime.ts:413` 用 `context.read(chunk.fileId, chunk.startOffset, chunk.endOffset)`
把**整块全文内联**进 index 任务 payload。索引阶段 = 程序分块 + 块全文直给；
`read_code` 工具仅用于边界不确定时补读邻近源码（最多 4 次）。
generate 阶段给单元范围；followup 阶段才是纯 agentic（search_code + read_code 自主检索）。

### 可靠性分层
- 程序硬保证（可信）：`context.validate()` 六处调用（runtime:223/225/248/301/1014、composeMultiFileFlow:22）
  证据覆盖；`completeModelRanges` 行列↔偏移一致（仅容忍"含行尾换行"一种写法）；
  `checkIndex` 块覆盖完整；`finish_reason==='length'` → ModelOutputTruncatedError 且不原样重试；
  `budget.middleware` 包 wrapModelCall 使工具循环无法绕过预算；runtime:435 禁止跨文件读；
  有 feedback 时跳过缓存强制重算。reserve 按 `chars+2000` **高估方向**估算，未回报 usage 时保留估算不记零。
- 结构半保证：单元 complete 与 boundary 标记一致、调用点 text/targetHint 逐字匹配、
  引用关系核对（同名不构成证据）、控制位置覆盖、retries 仅 1 次。
- 无程序保证：语义理解是否正确、漏掉的分支/循环、无 AST 交叉验证。证据充分 ≠ 理解正确。

### 已识别缺口
1. `analyzedRanges` 无 evidenceIds 绑定（schema.ts:109 仅偏移）——因块全文内联故"读过"为真，
   但 complete 只证明"每块处理过一遍"，不证明看懂。
2. 索引阶段证据是块级，约束力弱于 generate/verify 的精读级证据。
3. 无语义交叉验证，README 自认"模型事实仍可能漏解语义"。

### 容量风险（需实测）
按 chunkChars=2000，600 行文件约 12-15 块，20 文件约 240-300 块。
maxInput（480000）/ maxOutput（80000）很可能先于 maxCalls（120）耗尽，
报"分析预算已达上限"。用 LangSmith `model-complete` 事件的 inputTokens/outputTokens 实测累计曲线定位瓶颈。

### 提升正确性的优先级
1. 放大 `CODE2FLOW_MULTI_MAX_OUTPUT_TOKENS` / `MAX_INPUT_TOKENS`（当前瓶颈）
2. 提高 `CODE2FLOW_MAX_RETRIES`（现仅 1）
3. 必须配置 `CODE2FLOW_MODEL_CONTEXT_TOKENS`
4. **加 AST 交叉验证**（真正解药）：JS/TS 用 @babel/parser，其他语言用 tree-sitter，
   程序化提取 if/for/while/try/return 与模型 controlRanges 比对——唯一能把
   "证据正确"升级为"控制流正确"的手段。
