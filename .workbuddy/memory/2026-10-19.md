## code2flow 评估与观测体系（自建，非 LangSmith）

为让智能体"可测量地变好"，搭了观测 + 评估 + A/B 三件套。交付文档：

### 新增模块

- 观测层 `backend/src/ai/observability/`：`trace.types.ts` / `trace.collector.ts`（接口 + noop）/ `run-config.ts`（configHash 指纹）/ `trace.builder.ts`（JSONL sink + 采集器）/ `trace.sink.ts`（单例 + 开关）/ `observability.test.ts`

- 测试 `backend/src/services/flow-generation.trace.test.ts`

### 接线改动（既有文件）

`flow-generation.service.ts`（采集器生命周期收口 + 支持外部注入）、`ai/graph/code-flow.graph.ts`（`withStep()` 节点计时）、`code-flow.types.ts`（`trace?`）、`analyze-flow.node.ts`（透传）、`ai/chains/code-flow.chain.ts`（计轮次 + 采 token）、`agents/code-flow.agent.ts`、`ai/llms/openai.ts`（temperature 可配）、`.env.example`、`backend/package.json`、`.gitignore`

### 新增命令

- `npm run eval -- --label X [--limit N] [--concurrency N]` 跑评估
- `npm run eval:ab -- --a A.json --b B.json` A/B 对比（输出 Markdown）
- `npm run eval:traces [--file path]` 轨迹聚合（成功率/P50/P95/按 configHash 分组/节点耗时/失败聚合）

### 新增环境变量

`CODE2FLOW_TRACE`(on/off)、`CODE2FLOW_TRACE_FILE`、`CODE2FLOW_PROMPT_VARIANT`、`CODE2FLOW_MAX_RETRIES`、`DEEPSEEK_TEMPERATURE`

### 设计决策（重要）

- 选自建而非 LangSmith：评估数据含用户源码；项目风格是自控手写；无需外部账号；不加新依赖
- 轨迹存 `codeHash` + 长度，**不存明文源码**；结果只存统计量不存完整 mermaid
- 全部指标确定性可复现，未引入 LLM 裁判（可进 CI）
- 落盘失败只 warn 不抛出 —— 观测绝不能拖垮主链路

### 实测踩到并修掉的两个真实 bug

1. **外部注入采集器时未 catch** → 401/连接失败被记成 `outcome: success`，错误统计完全失真。已在 `runWithTrace` 的 externalTrace 分支补 `try/catch + setError`，并加回归测试锁定。
2. **CLI 脚本没加载 `.env`** → `run-baseline.ts` 里 provider 静默回退成默认 `langchain`（`.env` 实际是 `graph`），轨迹 `steps` 为空。已加 `dotenv` 显式加载 `process.cwd()/.env`。

- `npx tsc --noEmit` 干净；`npx vitest run` 30 tests / 5 files 全过
- 端到端实测：A 组（temp=0）4/4 通过，B 组（temp=0.8）4/4 通过但耗时 +172ms、token +22 → 结论"无收益"，证明对比链路有效
