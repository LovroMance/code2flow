# Usage 控制台设计

## 页面设计

用途：让开发者逐次核对流程图生成的 token 消耗。采用现有工具面板风格，顶部「工作区 / 控制台」导航，主体以横向紧凑表格展示；窄屏横向滚动，不挤压列内容。

沿用既有令牌：背景 `#111315`、面板 `#191c20`、边框 `#2c3036`、正文 `#e7e9ed`、强调色 `#9ccaba`；字体沿用 Aptos / Segoe UI / Microsoft YaHei UI。现有项目设计约束优先，不新增字体或组件库。

App 负责页面组合，工作区使用 v-show 保留实例与请求；控制台按需挂载，每次进入加载数据，刷新按钮在请求中禁用。页面具备加载、空列表、读取失败、观测关闭、扫描范围受限提示。

## 数据与调用

- `GET /api/usage` → controller → service → JSONL reader，查询设置 no-store。
- reader 最多读取日志末尾 4 MiB，跳过不完整首尾行与损坏记录，过滤追问及评估来源，按开始时间倒序返回最多 50 条。
- 后端 Zod 白名单校验，前端 unknown 响应通过契约守卫后使用。
- trace 新增可选来源、响应模型集合与 reportedRounds，保留旧文件和评估兼容。
- 请求级计数累加所有生成尝试；reportedRounds 与 llmRounds 比较，区分完整、部分、缺失；旧日志完整性未知。
- 不改 SSE，不新增环境变量、数据库或依赖；沿用单机应用的访问边界。

## 验证

使用本地模拟 OpenAI 服务检查真实 LangGraph 重试、供应商 usage 回调、成功/失败落盘和查询；文件测试覆盖旧日志、损坏行、扫描限制、排序及白名单；前端验证响应契约及 Vue 类型。浏览器验证若受工具环境阻断，应在交付中明确标注。
