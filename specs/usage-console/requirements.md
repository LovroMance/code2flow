# Usage 控制台需求草案

## 目标与范围

在现有 Code2Flow 页面增加「工作区 / 控制台」切换，让使用者查看每次流程图生成的 DeepSeek token 用量。第一版复用现有观测采集与 JSONL 记录，不增加数据库或图表依赖。

第一版只展示流程图生成记录；追问、Jev 语言识别用量、金额估算、趋势图、导出、筛选和配置修改暂不纳入。页面需明确标注「DeepSeek 生成用量，不含 Jev 语言识别」。

## 用户路径与展示

1. 用户在工作区提交生成，结束后切换至控制台查看记录。
2. 控制台进入时加载记录，提供「刷新」按钮；记录按开始时间倒序，第一版最多展示最近 50 条。
3. 每条记录显示：开始时间、模型名、成功/失败、输入 tokens、输出 tokens、总 tokens、重试次数。
4. 模型名优先显示响应返回的实际模型名；仅有配置值时标注「请求模型」，不将配置值称为实际模型。历史记录允许只有请求模型。
5. 页面使用现有深色背景、薄边框、绿色强调色和字体，以紧凑表格为主体；不新增统计卡片或图表。

## 验收条件

- 当用户切换工作区和控制台时，系统应保留当前源码、流程图、追问和生成状态；生成中的请求不因切换而取消。
- 当一次生成结束时，系统应记录本次所有模型调用的已返回 token 用量，包含校验失败后重试的用量，并在控制台合并为一条生成记录。
- 当生成失败且已有模型返回 usage 时，系统应展示失败记录及已知用量；不得只记录最后一次成功尝试。
- 当供应商没有返回 usage 时，系统应显示「未返回」；部分调用缺少 usage 时，应显示已知数值并标注「部分用量」，不得把缺失默认为真实零用量。
- 当进入或刷新控制台时，系统应明确展示加载、空记录和读取失败状态。
- 当浏览器刷新或后端重启后，系统应能读取已落盘记录；旧记录缺少用量完整性信息时不得声称用量完整。
- 当 CODE2FLOW_TRACE=off 时，系统应提示「用量记录已关闭」，并区分已有历史记录与新生成不再记录的情况。
- 当读取记录时，系统应按明确契约返回经过校验的白名单字段，不向前端返回源码、密钥、完整提示词或原始 trace。异常历史行不应导致整页不可用。
- 当存在历史追问或评估记录时，系统应只展示符合第一版范围的生成记录；新增来源标记用于区分在线请求与评估，旧记录来源未知时需说明。

## 已确认的代码现状

- `backend/src/ai/observability/run-callbacks.ts` 已从 LangChain AIMessage 的 usage_metadata 采集输入、输出和总 tokens。
- `backend/src/ai/observability/trace.builder.ts` 已按一次运行累加用量，包含模型调用轮数和重试次数；当前缺失 usage 会表现为零，需要补充完整性标记。
- `backend/src/services/flow-generation.service.ts` 在请求结束时写入 trace，覆盖成功和失败路径。
- `backend/src/ai/observability/trace.sink.ts` 使用 CODE2FLOW_TRACE_FILE 指定的 JSONL 文件，并支持关闭观测。
- 当前 trace 模型字段来自配置，尚未记录响应中的实际模型名；不能据此验证旧模型名是否由服务端路由。
- Jev usage 目前单独输出日志，不在生成模型 token 合计内。
- `frontend/src/app/App.vue` 当前只渲染 WorkspacePage，新增切换时需保留工作区组件实例。

## 后续设计方向（待细化）

- 后端遵循 controller → service → 记录读取模块，新增只读 usage 列表接口；使用 Zod 校验历史数据和响应契约，沿用原有 SSE。
- 前端按 pages / features / entities / shared 分层增加控制台页面、加载逻辑、usage 契约和 axios 请求，沿用现有视觉样式。
- JSONL 读取设置合理的扫描边界并处理末尾未完成行，避免记录增长后无界读取；响应最多返回 50 条。
- 验证覆盖：重试累加、失败保留已知用量、缺失/部分 usage、实际模型与请求模型区分、旧记录兼容、记录损坏、关闭观测、页面切换保留状态。

本范围已于 2026-10-21 获得用户实施授权；接口、采集扩展和控制台页面已按此范围实现。
