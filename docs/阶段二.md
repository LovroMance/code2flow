# 阶段二：Code2Flow 增强规划

## 阶段定位

在阶段一完成首版闭环后，继续补齐 Agent 的解释能力、会话能力和复杂前端逻辑分析能力，让产品从“可演示”升级为“更完整、更适合长期使用”的版本。

## 阶段二目标

在不改变项目总体方向的前提下，增强对复杂代码场景的理解、解释和交互体验，提升 Code2Flow 的产品完整度与 Agent 亮点表达。

## 核心增强功能（阶段二）

1. 支持对话式追问（如“解释这个循环为什么这样画”）
2. 支持多轮会话上下文延续
3. 支持更完整的流式输出体验和解释性内容返回
4. 增强 Vue / 前端逻辑识别能力

## Agent 技术要求

### 阶段二增强的 Agent 能力

1. **Chain of Thought 能力**：Prompt 中要求模型先进行内部分析，再输出最终结构化结果
2. **多轮对话状态管理**：使用 LangGraph 的 Checkpointer 保存会话
3. **解释型回答**：除了生成流程图，还能回答用户对分支、循环、异步链路的追问
4. **复杂逻辑理解**：提升对 Vue 响应式逻辑、生命周期和异步交互链路的识别能力

### 阶段二 LangGraph 扩展方向

在阶段一 `analyze -> validate` 主流程基础上，补充：

- 会话状态持久化
- 用户追问入口
- 针对历史分析结果的二次解释节点
- 更细粒度的错误恢复与结果补全

## 前端技术要求

### 阶段二增强的前端能力

1. 增加追问输入区和对话展示区
2. 保留流程图与代码编辑器双栏布局，并支持对话区整合
3. 优化流式渲染过程中的加载态、局部更新和错误提示
4. 在节点点击联动基础上，补充对解释文本与流程图节点的关联展示

## Prompt 模板增强方向

### 阶段二 Prompt 目标

在阶段一结构化输出 Prompt 的基础上，增加对解释能力和 Vue 复杂逻辑的约束。

增强要求：

- 能解释为什么某个 `if / else`、循环或异步调用被画成当前流程
- 能结合历史上下文回答追问，而不是重新分析全部代码
- 能识别 Vue 中更复杂的前端模式：
  - `watch` 触发的副作用链
  - `computed` 与状态变更之间的关系
  - 事件处理函数与异步请求的衔接
  - 生命周期钩子中的初始化逻辑

## API 与状态扩展方向

- 保留 `POST /api/generate-flow` 作为核心流程图生成接口
- 强化 `thread_id` 的实际用途，用于多轮会话延续
- 可新增追问类接口，或在现有 Agent 流中扩展对“分析结果 + 追问”的处理能力

## 部署与产品化增强

- 保持前后端部署方式不变
- 增强日志、错误处理和会话稳定性
- 为后续接入更多模型或更多代码类型保留扩展空间

## 面试话术（增强版）

“Code2Flow 的第一版解决的是代码逻辑可视化问题，第二阶段我继续把它往真正的 Agent 产品方向推进。

除了生成 Mermaid 流程图，我还支持多轮追问。比如用户可以继续问某个循环为什么这样建图、某个异步分支为什么单独拆节点。为了做到这一点，我用 LangGraph 的 Checkpointer 管理会话状态，让 Agent 能基于历史结果继续解释，而不是每次从头分析。

同时我把 Prompt 从通用流程提取扩展到了 Vue 前端语境，能更好理解生命周期、响应式副作用和状态派生逻辑，让这个工具更贴近真实前端项目。”

## 阶段二验收标准

1. 对话追问能基于上下文回答
2. 多轮会话能正确延续并关联历史分析结果
3. 能解释复杂分支、循环、异步链路的建图原因
4. 对 Vue 生命周期、`watch`、`watchEffect`、`ref`、`reactive`、`computed` 的识别更稳定
5. 流式输出在主结果之外，能够自然承载解释内容和补充信息
