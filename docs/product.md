# Code2Flow 产品范围与验收目标

核对日期：2026-10-22。本文保留原阶段规划中的有效需求，区分当前能力和待验证目标；实现细节见 [architecture.md](./architecture.md)。这里的验收项是后续验证依据，不代表已经全部测试通过。

## 用户与使用场景

面向需要理解代码执行路径的开发者、代码审查者和接手既有项目的维护者。主要场景是阅读一段源码，查看关键分支、循环、调用、异常及返回路径，通过图节点定位源码，再基于同一份分析追问。

当前输入支持单段粘贴代码，以及 v2 批量文本代码文件。多文件预览可调整相对路径，确认文件集合后直接生成，无需选择入口；本批源码默认同语言。覆盖语言以 `backend/src/domain/flow/language.ts` 为准。Vue 生命周期、watch、computed 和事件入口作为专项分析场景保留。语言可被选择和识别，不代表该语言的语义分析已经达到相同质量。

## 当前能力

| 能力     | 当前行为                                               |
| -------- | ------------------------------------------------------ |
| 代码输入 | Monaco 编辑、文件读取、示例代码、语言高亮              |
| 图生成   | 用户主动触发；自动语言检测、结构化输出、校验失败重试   |
| 流式展示 | 更新完整 Mermaid 快照，显示生成、完成和错误状态        |
| 图阅读   | 缩放、拖动、适应全图、原始字号、小地图和专注视图       |
| 源码定位 | 点击图节点滚动并高亮源码，同时预填节点追问             |
| 多轮追问 | 基于已有图、分析源码和历史问答返回解释，普通 JSON 响应 |
| 会话管理 | 新建、切换、重命名、删除、草稿自动保存与刷新恢复       |
| 用量查看 | 展示生成记录、重试和供应商回报 token 完整性            |

应用当前面向本机单用户使用。v2 跨文件分析默认最多20个文件、单文件200 KiB、合计2 MiB；全部文件进入索引覆盖检查，独立执行单元保留，有唯一绑定证据的调用或注册使用区别于局部控制边的连线。节点支持切换文件定位；修改任意草稿文件或路径后需要重新生成。仓库/压缩包导入、运行代码、源码到图的反向定位、解释文本点击定位、追问流式输出和多人协作均未实现。

多文件采用独立版本接口，旧单文件接口和历史会话保留。Embedding 未配置时明确降级为关键词检索；源码会发送至配置的生成、检测及向量服务。首次完整索引仍需阅读所有源码，不能承诺降低首次成本。验证记录与部署步骤见 [多文件实现与验证](./多文件代码分析实现与验证.md)。

## 验收目标

| 范围       | 应验证的结果                                                                               |
| ---------- | ------------------------------------------------------------------------------------------ |
| 基本控制流 | if / else、循环、switch、异常、提前返回和异步执行关系有源码依据，不臆造分支                |
| 节点粒度   | 同一职责的连续语句可以合并，关键路径边界仍独立可见                                         |
| 图与映射   | 最终 Mermaid 可实际渲染，节点与 mappings 一一对应，标签一致且无重复 ID                     |
| 原始位置   | 空行、注释、CRLF、多行语句和同一行多节点不造成定位偏移                                     |
| 多语言     | 分别评估语言检测与生成语义；unknown 和临时检测失败仍能使用通用规则                         |
| Vue 专项   | 生命周期、watch / watchEffect、computed、状态更新和事件入口不被串成虚假的顺序路径          |
| 流式体验   | 不完整片段不造成画布闪空；最终失败可见，缺少 done 不显示成功                               |
| 会话一致性 | 草稿保存失败保留内容；切换和刷新正确恢复；新生成清空旧问答，修改源码后不能继续使用旧图追问 |
| 追问解释   | 回答引用已有图节点与源码依据，能延续上下文，证据不足时说明，不输出内部推理过程             |
| 用量展示   | 重试用量累加，缺失回报不能展示成真实零值，评估和追问不混入生成列表                         |

## 仍有价值的后续工作

1. 补齐完整 Mermaid 解析、节点双向覆盖校验和多语言映射检查，使程序校验接近上述验收目标。
2. 扩充真实多语言与复杂 Vue 样例，分别记录识别准确率、实际渲染率、映射准确性和控制流语义问题。
3. 将旧规划中的 50–500 行源码作为待评估规模，按长度和复杂度分组记录成功率、首图 / 完成耗时与 token 用量；验证前不作为容量承诺。
4. 在现有节点追问基础上，评估解释文本与图节点的可点击关联，以及源码选择反向定位图节点的价值。
5. 如扩展到公开或多人部署，先处理源码调试日志、生成 SVG 安全边界、鉴权授权、并发协调和请求取消。

以上是候选改进方向，不代表已批准的开发排期。关于模型效果或阅读效率的对外表述，需要真实样本和测量结果支撑。
