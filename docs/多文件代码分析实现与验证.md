## 使用与配置

在工作区批量选择代码文件，预览文件名、相对路径和UTF-8字节数；可补充相对路径，确认后创建多文件会话。直接点击生成即可，不需要选择入口。默认本批源码同语言，Jev只识别一次；最终节点切换到相应文件定位。任意草稿内容、文件路径或清单改变后需重新生成；活动文件切换不影响快照一致性。

继续使用现有生成、Jev、checkpoint及重试环境变量。新增配置见 [backend/.env.example](../backend/.env.example)，必须明确填写 `CODE2FLOW_MODEL_CONTEXT_TOKENS` 为实际供应商窗口；不预设上下文容量。Embedding的地址、密钥和模型独立配置，未配置或失败时记录关键词降级。没有新增依赖或数据库迁移命令，业务表由版本表管理并在事务内初始化；不修改官方saver表。

源码会发送给配置的Jev、生成及Embedding服务。接口不执行上传源码，不读取上传路径所指的本机文件，不安装上传项目依赖。当前仍面向本机单用户、单进程运行，不增加项目管理或后台队列。

## 真实模型与成本对照

本地夹具验证协议和调度，不代表真实模型已正确识别所有语义。配置服务后运行：

```powershell
cd backend
npm run eval:multi -- src/eval/datasets/multifile-cases.json
```

案例包括Python、Go、TypeScript别名/同名函数和Vue独立响应式入口。评估只读取显式JSON中的源码，运行首次索引、缓存命中和直接全量输入三组，输出 `.code2flow/eval/multifile-report.json`。直接全量输入只用于离线对照，不接入产品路由；各组沿用相同的源码、检测结果和生成配置。首次/缓存组分别记录各角色usage，Embedding单独记录；直接组也做范围和关系证据校验。

标注指标分别检查关键控制位置、文件间关系的召回/精确情况及覆盖，仍需人工检查图的控制语义、独立入口、动态边界和映射精度。不能把局部标注得分、成功渲染或缓存调用数归零当作完整语义正确，也不能用估算token冒充账单。

本次未调用真实生成/Jev/Embedding服务，未宣称多语言准确率、召回率或成本收益通过。浏览器连接工具报告既有浏览器配置占用，未完成真实浏览器验收。部署后还需验证：上传/预览、跨文件节点定位、切换文件视图、刷新恢复、修改失效、断流取消、渲染失败重试和删除。

## 容量与错误边界

文件上限不是模型容量保证。索引补读或局部生成超上下文/总预算时保留已成功索引，返回未完成范围，不发送完整done；重新生成复用有效缓存。无法核对大单元分段连接时返回超限，不随意顺序拼接。未上传依赖、动态目标、同名歧义作为边界诊断，可在覆盖完成后正常返回结果。

模型事实仍可能漏解语义；程序覆盖检查仅证明所有原文范围进入成功任务。跨文件关联采用保守证据校验，无法证明的模块映射、默认导出或动态注册保持未解析，不保证所有语言的关系都能被自动确认。没有新增Graph RAG、图数据库、解析器前置条件或独立向量服务。
